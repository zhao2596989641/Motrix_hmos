## 为什么不是"用上游的托管安装"

上游 FFmpeg 只有 **darwin / linux / win32** 三个平台的签名发布包
（`src/core/ffmpeg/verified-release.ts` 的平台枚举），鸿蒙不在其中；
`installServerFfmpeg()` 遇到非这三平台直接返回 `unsupported`，
所以设置页的「下载 FFmpeg」在鸿蒙上永远不可用。

替代方案有两条：

| 方案 | 代价 | 结论 |
|---|---|---|
| A. 调 harmonybrew `brew install ffmpeg` | 15 个依赖（x264/x265/dav1d/lame/…），几百 MB，且污染用户的 brew | 不采用 |
| **B. 自建最小静态 ffmpeg 随包** | 一次编译 + 4.3 MB 包体 | **采用** |

## 构建方法（可复现）

工具链：CLT clang（`aarch64-linux-ohos` 目标，自带 sysroot），源码 `ffmpeg-7.1.tar.xz`。

关键点：ffmpeg 的 `configure` 会编译并**当场运行**探测程序，而鸿蒙对未签名 ELF
一律拒绝执行（EACCES）。所以写了一个 cc 包装器
（`codes/.buildcache/ffmpeg/cc-sign-wrapper.sh`）：链接完成后剥掉占位 `.codesign` 段、
用 `binary-sign-tool -selfSign 1` 自签，再交给 configure 运行。

配置（`--disable-everything` 只开下载器用得到的部分）：

```
--target-os=linux --arch=aarch64 --disable-network --disable-autodetect
--enable-ffmpeg --enable-ffprobe --disable-ffplay --disable-avdevice
--enable-protocol=file,pipe
--enable-demuxer=mov,matroska,mpegts,flv,mp3,aac,wav,flac,ogg,avi,image2,hls,mpjpeg
--enable-muxer=mp4,matroska,mpegts,mov,ipod,mp3,adts,wav,flac,image2
--enable-parser=h264,hevc,aac,mpegaudio,vp9,av1,opus,flac,mjpeg
--enable-bsf=h264_mp4toannexb,hevc_mp4toannexb,aac_adtstoasc,extract_extradata,vp9_superframe
--enable-decoder=h264,hevc,aac,mp3,flac,pcm_s16le,vp9,av1,opus,vorbis,mjpeg
--enable-encoder=aac,flac,pcm_s16le,mjpeg
--enable-filter=aresample,anull,null,scale,format,copy,concat,atrim,trim
--enable-small --disable-debug
```

产物：`ffmpeg` **4.28 MB**、`ffprobe` 4.17 MB（strip 后），许可证 **LGPL-2.1+**
（没有 GPL 组件，所以随包分发也没问题）。

## 本机实测（同一台设备）

```
$ ffmpeg -version
ffmpeg version 7.1
$ ffmpeg -i "<某个 m4a>"            # 探测
  Duration: 00:00:10.30, bitrate: 133 kb/s
  Stream #0:0: Audio: aac (mp4a / 0x6134706D), 48000 Hz, stereo
$ ffmpeg -i "<m4a>" -c copy out.m4a # 流拷贝重封装
speed=5.13e+03x   ✅ 输出 165 KiB
```

detection 走 core 的 `env` 层，`active.version = 7.1`（用真实 HAP 内的同一份二进制验证过）。

## 打包方式

沿用 aria2c 那套官方 `hap-bin` 通道：

1. `build/bin/ffmpeg`（构建时由 `sign-elf-appcert.sh` 用**应用证书**签名）；
2. `build-hap.sh` 第 4b 步复制成 `entry/libs/arm64-v8a/ffmpeg.bin`
   （必须带 `.bin` 后缀，否则 hap-sign-tool 的 `IsNativeFile` 会漏掉、安装报 9568393）；
3. `module.json5` 的 `executableBinaryPaths` 声明 `libs/arm64-v8a/ffmpeg.bin`；
4. 宿主启动时 `resolveBundledExecutable('ffmpeg')` 找到它，注入
   `MOTRIX_FFMPEG_PATH`，core 的探测层直接把它判为 `active`。

## 验证清单

1. 装 r64 → 设置 → 集成 → **FFmpeg** 区域应显示「已就绪 / 版本 7.1」，
   来源是「环境变量」层；
2. 浏览器扩展抓一个 HLS/DASH（音视频分离的）任务 → 下载完成后应能**自动合并**成单文件；
3. 若之前手动填过 `ffmpegBinaryPath`，把它清空再刷新（手填项优先级最高）；
4. 回归：CLI 卡片仍显示已安装（0.5.0）、开屏、扩展、下载正常。

## 已知限制

- 构建里**没有** libx264 / libmp3lame 等外部编码器：转码到 H.264、导出 MP3 会失败；
  DASH/HLS 的 `-c copy` 合并、探测、AAC/FLAC/WAV 提取都正常。
  真需要转码再补一轮带 x264 的构建（包体会大很多）。
- 没有网络协议（`--disable-network`）：ffmpeg 只处理本地文件。
  合并任务的文件本来就是 aria2 下到本地的，够用。
