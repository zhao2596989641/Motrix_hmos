## 这个包要验什么

### ① 动态沙箱有没有生效（看数据目录搬没搬）

- `ability-diag.log` 开头会有一行：
  `sandboxType probe filesDir=… cacheDir=… bundleCodeDir=…`
  - `filesDir` 若仍是 `/data/storage/el2/base/haps/entry/files` ⇒ 动态沙箱**未**自动生效
    （很可能需要 App 显式切换，权限只是"允许"）；
  - 若变成 `/storage/Users/currentUser/appdata/com.lyldeer.motrix/...` ⇒ 动态沙箱已生效，
    此时**任务列表/设置会看起来清空**（旧数据还在老目录），需要我下一轮做迁移。
- `cli-probe.json` 的 `sandbox` 段也会记录 `sandboxHome` / `dataDir` / `cwd` / 旧 el2 目录是否还在。

### ② exec 有没有放开（本轮核心问题）

`cli-probe.json` 的 `spawn` 段：

| 探针 | 期望变化 |
|---|---|
| `brewNodeReal`（`Cellar/node/26.12.0/bin/node -v`） | `EPERM` → **ok** 说明自签 ELF 可执行 |
| `brewReal`（`Homebrew/bin/brew --version`） | `ENOENT` → **ok** 说明 shebang 能解析 |
| `brewRealViaSh` | `126` → **ok** 说明脚本可跑 |
| `brewNodeVersion` / `brewVersion`（symlink 路径） | 若仍 `EACCES` ⇒ symlink 沙箱策略未变，需走真实路径 |

### ③ 顺便回归

- 开屏（app logo → m·o 字标）、扩展仍连着、下载一个小文件正常。

## 判读与下一轮

- **exec 放开** ⇒ 可以照 BitFun 的做法真正实现「应用内 brew/npm 安装」，r63 做 CLI 安装器；
- **exec 仍 EPERM** ⇒ `CUSTOM_SANDBOX` 与 exec 无关，把该权限注释回去（避免后续安装风险），
  CLI 集成按"检测 + 手动命令"或"自己下 npm tarball 解包"收口；
- **动态沙箱生效** ⇒ 无论 exec 结果，都要先做数据迁移（把旧 el2 目录数据搬到新目录，
  或干脆回退该权限），再谈功能。
