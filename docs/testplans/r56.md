## 三个问题

### 1. 开屏"大 logo → 小 logo → m·o 字标"三段跳

根因是三段不同的 UI 各画了一个 logo：

| 阶段 | 谁画的 | 原来 |
|---|---|---|
| ① 系统启动页 | `startWindowIcon: $media:startIcon`（512×512） | **放多大画多大** ⇒ 巨大 |
| ② ArkUI 开屏遮罩 | `Index.ets` 里 `Image(startIcon).width(112)` | 小 |
| ③ 网页自带 loading | `#renderer-boot`（`mo-logo.svg` 字标 + shimmer） | 第三段 |

修法：
- 改用**增强启动页**（`startWindow` → `profile/start_window.json`）：整窗背景图
  `splash_background.png`（logo 已合成在图中央，1200×800，浅/深两套），
  `startWindowBackgroundImageFit: Contain`，与 ArkUI 遮罩**用同一张图** ⇒ ①→② 像素级一致。
- 保留 `startWindowIcon: $media:start_window_icon`（192×192）作为旧系统/简易启动页兜底。
- ArkUI 遮罩不再画 112vp 图标，改成同一张 `splash_background` 全屏 Contain。
- 遮罩撤除时机从 **onPageEnd**（HTML 到了）推迟到**渲染层真正挂载**
  （注入脚本的 `html.mtx-booting` 被移除；每 120ms 轮询，最多 12s 兜底）。
- 注入 CSS 把网页自带 `#renderer-boot` 在鸿蒙壳里永久隐藏（外部浏览器形态不受影响）。
- 图片由 `scripts/make-splash-assets.mjs` 生成（纯 Node PNG 解码/缩放/合成，无外部依赖）。

### 2. 集成卡片"扩展通道还没启动"（r55 真机日志定位）

宿主选了桥端口 `16802`，随后 aria2 引擎因 16800/16801 被占也顺延到 **16802**，
桥 `listen EADDRINUSE` ⇒ 整个 MDXP 桥启动失败。

修法：桥端口候选从 `16801..16806` 改为 **`17891..17896`**（避开 aria2 RPC 的 16800+20 顺延段）。
集成卡片地址会变成 `ws://127.0.0.1:17891`（第一个空闲口）。

### 3. 托盘左键面板"下载任务"卡太高

`SystemTray.PANEL_HEIGHT` 从 **880 → 740**：卡片按 layoutWeight 等比压缩，
下载任务列表约为原来的 2/3；列表本身仍可内部滚动。
