## 两个问题

### 1. 开屏"空前地长"（r56 的 12 秒等待）

真机 `arkts-diag.log` 证据：

```
17:09:45.884 onPageEnd appLoadRequested=true
17:09:58.186 ready poll timeout after 100 tries, force ready   ← 12.3s
```

r56 把撤开屏的判据改成"渲染层挂载（`html.mtx-booting` 被移除）"，但轮询
`runJavaScript` 一直读到未移除，直到 100 次超时才放行 ⇒ 开屏停了 12 秒。

修法（按维护者定义的三段，合并二三段）：
- ① 系统增强启动页：保持现在的 app logo（`splash_background.png`）；
- ② ArkUI 开屏遮罩：改为 **m·o 字标**（`splash_wordmark.svg`，112×25、opacity .85）；
- ③ 网页自带 `#renderer-boot`：同一个 m·o 字标（带 shimmer），注入 CSS 把它放大到
  112×25/0.85 与原生一致；
- 撤遮罩时机恢复为 **onPageEnd**（约 1s），②→③ 同尺寸同透明度，拼接成一段连续的
  "字标加载"，不再等 React 挂载、不会再 12 秒。

### 2. 扩展点配对，Motrix 没有任何 PIN 弹窗

r56 服务端日志：

```
Extension pairing codes are available through the local interactive command:
motrix-admin extension pair. Configure an HTTPS MOTRIX_PUBLIC_URL or explicitly
allow operator HTTP to display codes in the Web UI.
```

即：`operatorDelivery: 'local'` 时，配对请求事件被服务端 `filterExtensionPairingSnapshot` /
事件过滤直接丢掉，Web UI（我们的 ArkWeb 界面）永远收不到 PIN。

修法：宿主环境补两条（只对回环 HTTP 放行）：

```
MOTRIX_PUBLIC_URL=http://127.0.0.1:<控制端口>
MOTRIX_ALLOW_INSECURE_OPERATOR_HTTP=1
```

⇒ `operatorDelivery` 变 `web`，配对请求与 8 位配对码会通过事件流送到渲染层，
`usePairRequestPrompts` 在窗口里弹提示（含配对码 + 复制按钮），用户把码输进扩展即可。

> 本地回环用 HTTP 安全；公网仍只认 HTTPS（上游规则未改）。
