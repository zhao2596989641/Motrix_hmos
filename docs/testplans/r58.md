## 下一步：ACL 探针（需要一次 DevEco 重新签名）

`READ_WRITE_USER_FILE` 是 system_basic 受限权限，必须由华为在签名 profile 里下发 ACL。
思路与 r50 的 JIT ACL 相同，但这次需要先让华为重新生成 profile：

1. 在工程里解注权限：
   ```sh
   node scripts/patch-module-permissions.mjs enable user-file
   ```
2. 打开 DevEco Studio → File → Project Structure → Signing Configs，
   勾选 **Automatically generate signature** → Apply/OK（重新生成 `.p7b`）。
   如果华为侧要求审批，按提示提交（场景选「IDE / 开发调测工具读写 PC/2in1 用户目录」）。
3. 把 `~/.ohos/config/*.p7b` 的更新时间（或直接让维护者告知完成）告诉我。

我会用 `hap-sign-tool verify-app -outProfile` 解出 profile，检查
`acls.allowed-acls` 是否包含 `ohos.permission.READ_WRITE_USER_FILE`：

- **包含** ⇒ 用 `MOTRIX_ENABLE_USER_FILE_PERMISSION=1 sh scripts/build-hap.sh` 出探针包；
  装好后 `cli-probe.json` 的 `userFile.harmonybrew` 应变成 `exists:true, count:…`，
  `brewScript.readable` 应为 true —— 那 CLI 集成就有戏了。
- **不包含** ⇒ 说明自动签名拿不到这条 ACL，只能去开发者中心按「受限权限申请」提交材料
  （IDE/开发调测工具场景），审批后再签。
