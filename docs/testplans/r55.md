## 改了什么

1. **浏览器扩展：把上游 MDXP 桥接通道打开（只监听回环）**
   - 以前宿主动手把 `MOTRIX_MDXP_PORT` 置 0（随机端口、关掉固定端口），扩展根本找不到地址。
   - 现在宿主先在 `16801…16806` 里抢一个空闲端口，并同时设置：
     · `MOTRIX_MDXP_HOST=127.0.0.1`（只回环）
     · `MOTRIX_REMOTE_EXTENSION_ENABLED=1`
     · `MOTRIX_REMOTE_EXTENSION_PUBLIC_URL=ws://127.0.0.1:<端口>`
   - 这样服务端的"远程扩展"能力打开（`clientPairing.extension=true`），
     集成卡片不再显示"扩展配对不可用"，而是显示扩展管理界面 + 本机连接地址。
2. **集成卡片新增鸿蒙专属连接提示**
   - 显示 `ws://127.0.0.1:<实际端口>` + 一键复制；
   - 三步说明：装 Chromium 版扩展 → 添加远程服务器填地址 → 输入 Motrix 显示的 8 位配对码；
   - 提醒：开发者模式加载的扩展 ID 与商店版不同，要先在「可信扩展」里加 ID。
3. **CLI 环境探测（只读诊断，不改 UI）**
   - 宿主在 ready 后 20s 写 `<filesDir>/cli-probe.json`：
     · 目录可见性：`~/.harmonybrew`（bin/Cellar/lib/node_modules）、`~/npm/lib/node_modules`、`~/.npmrc`；
     · spawn 结果：`/bin/sh`、`command -v node/npm/brew`、brew 的 node/brew/npm-cli。
   - 目的：确定端侧到底能不能像 BitFun 那样 spawn 用户目录里的 brew/node（决定 r56 的集成卡片怎么做）。

> 本轮**没有**改下载逻辑，也**没有**加新权限。CLI 集成等 `cli-probe.json` 回来再动手。

## 验证清单

1. 装 r55 → 设置 → 集成：**不再**是"扩展配对不可用"，能看到「浏览器扩展」区块与
   「连接本机 Motrix（鸿蒙）」提示，里面有一行 `ws://127.0.0.1:16801`（或其它端口）。
2. 在**华为浏览器 / 海泰浏览器**里安装 Chromium 版 Motrix Extension：
   - 商店能装就装商店版；不能就用开发者模式加载解压包。
3. 打开扩展 → 设置 → 添加远程服务器 → 粘贴上面那行地址 → 保存 → 点「配对」。
4. 回到 Motrix：应出现配对请求（弹窗/通知），确认后把 **8 位配对码**输入扩展。
5. 配对成功后：在网页里右键「Download with Motrix」，任务应出现在 Motrix 里并开始下载。
6. 发我这几样（**不用整理**，直接丢 `logs/`）：
   - `logs/cli-probe.json`（本轮最重要，决定 CLI 那块的可行性）
   - `logs/node-output.log`（搜 `bridge port` / `MDXP bridge listening`）
   - 集成卡片截图

## 已知可能

- 如果集成卡片显示「扩展通道还没启动」：说明桥没起来（端口被占或权限），发日志即可。
- 如果扩展连不上：先确认地址端口与日志里的 `MDXP bridge listening` 端口一致；
  华为浏览器可能对 `ws://127.0.0.1` 有额外限制，把扩展的报错也一起发我。
